# Clervo autonomous build

1. Resolve the concrete task from the owner's instruction and the active issue,
   pull request, branch, or explicitly scoped work. Read `CLAUDE.md` for the
   repository-wide truth and safety rules. `ROADMAP.md` is public product
   direction only, not an internal execution queue.
2. Preserve owner work and verify the current contracts and canonical
   catalog/launch-state relevant to the task.
3. Invoke `$clervo-authority-lock` for all public data and visible behavior.
4. Build shared HTTP/OpenAPI projections, SDKs, MCP, and conformance before
   making user-facing surfaces depend on unproven contracts.
5. Implement truthful request-to-result experiences with real navigation,
   evidence, errors, and recovery behavior appropriate to the scoped task.
6. Use `$clervo-cinematic-production` for canonical physical media and
   `$clervo-runtime-parity` for browser implementation when relevant.
7. Use `$clervo-experience-activation` for navigation, proof surfaces, docs,
   and developer onboarding when relevant.
8. Harden mobile, fallbacks, accessibility, performance, and assets.
9. Invoke `$clervo-final-proof`, repair failures, and report only genuine
   residual risks or owner blockers.

Keep moving through reversible engineering decisions. Generated media is
exploration, not product proof. Never invent completion or public availability.
If a production-sensitive step needs private operational context that is not in
the current task, stop before that step rather than reconstructing it from
historical public artifacts.
