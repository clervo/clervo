# Clervo autonomous build

1. Read `ROADMAP.md` at the repository root for scope, order, and status.
   `docs/product/CLERVO-V6-VISUAL-AUTHORITY.md` is archived reference for
   visual direction only and carries no product authority.
2. Preserve owner work and verify the current release-candidate contracts.
3. Invoke `$clervo-authority-lock` for all public data and visible behavior.
4. Build the shared HTTP/OpenAPI projection, SDKs, MCP, and conformance before
   making the site depend on them.
5. Implement a truthful request-to-receipt product slice with real navigation,
   history, evidence, error, and recovery behavior.
6. Use `$clervo-cinematic-production` for canonical physical media and
   `$clervo-runtime-parity` for the browser implementation.
7. Use `$clervo-experience-activation` for navigation, Proof Lab, docs, and
   developer onboarding.
8. Harden mobile, fallbacks, accessibility, performance, and assets.
9. Invoke `$clervo-final-proof`, repair failures, and report only genuine
   residual risks or owner blockers.

Keep moving through reversible engineering decisions. Generated media is
exploration, not product proof. Never invent completion or public availability.
