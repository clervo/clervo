# Clervo continuous engineering policy

Read `CLAUDE.md` before selecting work.

Current product lifecycle and availability are established from directly
observed deployed behavior and the canonical catalog/launch-state data in this
repository. `ROADMAP.md` is public product direction only; it is not an internal
operations log, deployment runbook, payment ledger, recovery authority, or
private milestone tracker.

Work selection comes from the owner's explicit instruction and the concrete
issue, pull request, branch, or scoped task being worked on. Files under `docs/`
are research/history unless the current task explicitly names one as input.
Observed behavior outranks prose when establishing current system state.

Codex may inspect, implement, refactor, test, document, and commit ordinary
repository changes within the boundaries defined by the task and agent
instructions. Routine local work, repairs, dependency installation, bounded
technical research, and commits do not require per-task owner approval.

Use focused checks during implementation and consolidated checks at meaningful
boundaries. Preserve truthful failures and prior evidence without allowing
historical proof artifacts to define unrelated future work. Public availability
claims require external evidence; a passing local test alone is not sufficient.

Do not publish operational continuity that does not need to be public. In
particular, public planning/status documents must not become a store for
credential or secret-version information, wallet material, deployment or
worker identifiers, rollback targets, private branch recovery state, internal
spending authorizations, supplier credentials, or incident-recovery details.

Owner action is required for real spending or payment, missing credentials or
interactive account steps, irreversible production or customer-data actions,
unrelated-infrastructure operations, and non-technical legal, contractual,
branding, pricing, or business choices. Never expose secrets, weaken security
or contracts, bypass provider terms, or overstate lifecycle and product
readiness.

If a production-sensitive action requires private operational context that is
not present in the current task, stop before that action rather than recreating
private state from historical public artifacts.
