# Clervo continuous engineering policy

`ROADMAP.md` at the repository root is the single planning authority. The full
agent instructions are in `CLAUDE.md`. Read both before selecting work.

`docs/` is an archived research library: useful for facts and history, not a
current directive. Material outside this repository is not project authority
unless the owner explicitly makes it so. Observed behavior outranks prose when
establishing current system state.

Codex may inspect, implement, refactor, test, document, and commit ordinary
repository changes within the boundaries defined by the roadmap and agent
instructions. Routine local work, repairs, dependency installation, bounded
technical research, and commits do not require per-task owner approval.

Use focused checks during implementation and consolidated checks at meaningful
boundaries. Preserve truthful failures and prior evidence without allowing
historical proof artifacts to define unrelated future work. Public availability
claims require external evidence; a passing local test alone is not sufficient.

Owner action is required for real spending or payment, missing credentials or
interactive account steps, irreversible production or customer-data actions,
unrelated-infrastructure operations, and non-technical legal, contractual,
branding, pricing, or business choices. Never expose secrets, weaken security
or contracts, bypass provider terms, or overstate lifecycle and product
readiness.

Do not create parallel planning, status, gate, or readiness documents. Update
the canonical roadmap instead.
