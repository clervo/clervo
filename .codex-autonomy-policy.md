# Clervo Codex Autonomy Policy

Codex has autonomous technical permission inside the dedicated Clervo
development container and repository.

It may, without requesting command approval:

- inspect and modify Clervo repository files;
- run Git, npm, tests, verifiers, builds, and local services;
- install development dependencies required by an authorized ticket;
- use bounded network access required by an authorized ticket;
- create evidence, documentation, fixtures, and commits;
- repair ordinary repository, test, lint, typecheck, and tooling failures;
- complete the current authorized ticket, commit it, verify it, and stop that
  worker cycle;
- in a fresh dispatch cycle, admit and execute the next exact local ticket under
  the NPLAN.4 standing completion authority when every admission gate passes.

This permission does not override the Clervo master plan, stage order,
ticket scope, truthful-claims policy, or stop conditions.

Still prohibited unless the active ticket explicitly authorizes it:

- real USDC payments or wallet transactions;
- production deployment or production data mutation;
- cloud billing, IAM, account, or secret changes;
- revealing, logging, or committing secret values;
- deleting host backups or unrelated projects;
- beginning an ad hoc, vague, proposed-only, or non-admitted next ticket;
- beginning any later roadmap stage, product-core implementation, shared-surface
  pass, release action, or expansion before the exact active ticket and every
  preceding gate authorize it;
- silently changing providers, product claims, or architecture;
- destructive Git history rewriting;
- bypassing provider terms, robots rules, access controls, or quotas.

NPLAN.4 removes repeated owner approval only for exact tickets admitted by
`infra/control-plane/autonomous-completion-policy.v1.json`. Required paid,
eventually-paid, and trial-to-bill third-party API cash spend is USD 0.
Unmanifested external spend is USD 0. Credentials, cloud/IAM/billing/secrets,
production, DNS/domain/email/registry, external messages/customers, legacy
mutation, and wallet/payment effects remain blocked until an exact finite owner
input package supplies the missing identity, resource, operation, cost, cleanup,
evidence, expiry, and stop boundary **and** the owner separately authorizes the
exact action. Workspace JSON is non-authoritative until an owner-controlled
read-only trust root, detached signature verification, independent revocation,
and mediated enforcement are implemented.

Codex must implement, test, verify, document, commit, post-commit check, report,
and stop the worker at the end of each authorized ticket. A fresh dispatch
cycle—not the closing worker—may admit the next exact ticket. Failed evidence is
preserved; sealed/final/once-only qualification is never rerun or tuned. A
receiver public address is accepted for x402 `payTo`; a receiver private key is
never requested or accepted.
