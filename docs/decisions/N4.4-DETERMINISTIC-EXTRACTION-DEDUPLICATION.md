# N4.4 deterministic extraction and content deduplication decision

Date: 2026-07-30

## Decision

Extraction accepts only bytes bound to a successful N4.3 fetch receipt. The receipt must identify the exact final URL, supported MIME type, byte length, SHA-256 digest, successful content hop, and an allowed or explicitly archive-not-applicable robots decision. The implementation does not fetch, render JavaScript, load subresources, or execute page content.

UTF-8 `text/plain`, `text/html`, and `application/xhtml+xml` are handled by a bounded worker thread with explicit memory, stack, output, and wall-clock limits. HTML processing is a deliberately small non-executing tokenizer: comments, declarations, tags, and active/non-content regions are removed; a fixed entity set and valid numeric entities are decoded; text is normalized with Unicode NFKC and deterministic whitespace rules; and retained segments carry exact offsets into normalized text. Malformed UTF-8/HTML, empty output, unsupported formats, receipt mismatch, output overflow, and worker failure fail closed.

Instruction-like webpage content is retained as attributable untrusted evidence and flagged; it is never interpreted as an instruction. This is the first prompt-injection data boundary, not a complete model-facing defense or claim that all adversarial instructions can be detected.

Content deduplication revalidates every supplied extraction record, then chooses deterministic winners by canonical final URL and extraction ID. Exact duplicates use normalized-text SHA-256 equality. Near duplicates use case/punctuation-insensitive five-word shingles and integer Jaccard basis points with an explicit caller threshold constrained to 5,000–10,000. Exact, near, and retained counts remain separate, and input limits or later ranking truncation cannot inflate duplicate counts.

## Explicit exclusions

- No browser, JavaScript rendering, CSS-layout interpretation, PDF/JSON extraction, OCR, language detection, model, synthesis, query rewriting, provider adapter, database, queue, HTTP route, payment, cloud, IAM, or deployment.
- Worker-thread resource isolation and a non-executing parser reduce parser/event-loop risk but are not an OS sandbox or security claim for arbitrary native parser libraries.
- Boilerplate removal is structural and conservative; no claim of perfect main-content extraction or calibrated near-duplicate threshold is made.
- Instruction-like-text warnings are evidence labels, not sanitization and not permission to pass retrieved text into a model without a later prompt boundary.

## Rejected alternatives

- Parse fetched HTML in the main execution path: rejected because malformed or expensive content needs a separately terminable resource boundary.
- Use regular-expression stripping without receipt binding or exact offsets: rejected because provenance and citation continuity would be unverifiable.
- Add a browser or third-party parser without a focused dependency/security decision: rejected because N4.4 requires deterministic non-executing extraction, not active rendering.
- Treat normalized hash inequality as uniqueness: rejected because small templates, mirrors, and syndicated edits require content-level similarity.
- Use embeddings or a model for duplicate decisions: rejected because they add cost, nondeterminism, and prompt exposure before deterministic evidence mechanics are complete.
