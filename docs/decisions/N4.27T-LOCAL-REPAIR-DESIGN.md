# N4.27T local repair design

**Decision date:** 2026-08-01

## Evidence boundary

Only the immutable N4.27S decision and truthful summary supplied the three
failure classes. Final corpora, labels, raw output, evaluator output and
scorecard are excluded from the repair workspace. N4.27T uses new identities,
fixtures, splits, hashes and a later isolated run.

## Current-practice preflight

- The npm public Registry API documents exact package metadata endpoints and a
  bounded `/-/v1/search` endpoint. Exact package identities therefore use the
  metadata endpoint before full-text search:
  <https://github.com/npm/registry/blob/main/docs/REGISTRY-API.md>.
- GitHub repository metadata and search remain separate read-only REST
  interfaces with separate search rate limits. N4.27T uses exact repository
  identity when present, bounded search otherwise, never retries through a rate
  limit, and requires the versioned API header:
  <https://docs.github.com/en/rest/search/search> and
  <https://docs.github.com/en/rest/rate-limit/rate-limit>.
- Playwright's container guidance recommends a non-root browser user with an
  appropriate seccomp boundary, an init process to reap children, dedicated
  Chromium shared memory, and exact browser/tooling version matching:
  <https://playwright.dev/docs/docker>.
- Google Cloud documents that `--async` deletion returns before completion and
  that some dependent resources are not guaranteed to be deleted. Replacement
  creation must therefore wait for a direct zero-resource inventory and zero
  pending-operation proof, not merely a successful delete submission:
  <https://cloud.google.com/sdk/gcloud/reference/container/clusters/delete>.

## Decision

### Developer registry

Parse only conservative exact identities. `owner/repository` uses the GitHub
repository endpoint; a valid npm package name uses the exact package metadata
endpoint. Otherwise use one bounded, normalized search query. Response
normalization never trusts HTML, never downloads code/tarballs, and retains
official metadata attribution, timestamps and licensing caveats.

### Browser and hostile content

Keep one fresh browser process per attempt. Add an init/reaper, a memory-backed
`/dev/shm`, an absolute supervisor deadline with explicit preflight/render/
cleanup budgets, process-group termination and a mandatory post-run orphan and
state audit. Qualification fixtures are dedicated immutable JavaScript pages
and hostile evidence pages; hostile text remains untrusted evidence and cannot
change routing, ranking, payment, tools, citations, secrets or policy.

### Resource overlap

Use a two-phase admission gate: inspect and classify every ticket-owned
resource and pending operation, then calculate candidate plus residual daily
exposure. Any active chargeable resource, pending deletion, unknown state,
unlabelled candidate, stale inventory, missing zero-resource proof or amount
above the ceiling rejects creation. A delete command is not deletion evidence.

## Rejected approaches

- Query-specific result pinning: it would overfit the repair corpus.
- Reusing N4.27S final tasks or labels: it would violate the sealed boundary.
- Increasing browser retries: it hides startup defects and changes the gate.
- `--no-sandbox`, root Chromium or broad network egress: unacceptable security
  regression.
- Asynchronous delete followed by immediate replacement create: repeats the
  observed cost-overlap class.
- Paid search APIs: violate the zero-paid-API rule.

## Truth boundary

Repository-local success proves only repair readiness. It does not close a
Stage 4 blocker or prove staging reliability, commercial quality, a deployed
paid route, cost-cap compliance, Search reference-pattern status or Stage 5.
