# N4.13 isolated JavaScript retrieval decision

Date: 2026-07-31

## Decision

Add a versioned, fail-closed JavaScript retrieval boundary behind an injected browser adapter. Invocation requires a fresh successful N4.3 static fetch receipt whose final robots decision is `allowed`, whose final response is renderable HTML/XHTML, and whose exact preflight body is SHA-256 bound into the render receipt.

The core, not the adapter, owns browser-network authorization. Every requested resource must be same-origin, HTTP(S), DNS-resolved to public addresses, counted before asynchronous resolution, and represented exactly once in the final transcript. The adapter must attest a sandboxed disposable browser process with ephemeral storage, blocked service workers/downloads, denied permissions, and core-authorized network interception. Rendered output is released only after request-count, network-byte, rendered-byte, connected-address, status, MIME, origin, transcript, isolation, deadline, and cancellation validation.

## Consequences

- Adapter failures expose only stable safe codes; renderer exception text is not retained.
- Cross-origin traffic is deliberately blocked, including otherwise common CDN resources, to keep the first boundary narrowly auditable.
- A renderer implementation must enforce the supplied frozen policy and authorization callback; a forged attestation or incomplete transcript causes atomic output rejection.
- This is repository evidence for the boundary contract and adversarial behavior only. No Chromium/Playwright dependency, concrete browser adapter, live browser process, external site, or staging deployment was exercised.

## Rejected alternatives

- Unrestricted browser egress: rejected because it bypasses SSRF, DNS-rebinding, and byte/request accounting.
- Adapter-owned allowlists: rejected because the untrusted execution boundary would authorize itself.
- Persistent browser pools or profiles: rejected because cookies, storage, service workers, permissions, and process state could cross retrievals.
- Browser-first retrieval without static preflight: rejected because it could bypass the existing lawful-use, robots, redirect, MIME, and target-safety boundary.
