# N4.6 retrieval evidence assembly decision

Date: 2026-07-30

## Decision

`assembleRetrievalCandidates` is the deterministic boundary between N4.5 federation observations and N4.1 citation-bound search evidence. It reconstructs and hash-matches the N4.2 qualification snapshot, requires both selected paths to permit `transient_extraction`, revalidates federation attempts and observation provenance, and refuses to invoke fetchers when identity, time, URL, count, provider/path, ordinal, or raw-response bindings are invalid.

Candidates are processed in stable federation order under explicit batch, byte, output, worker, result, and absolute-deadline limits. Each selected observation receives a deterministic fetch ID and extraction ID, passes through the N4.3 bounded-fetch contract and the N4.4 worker extraction contract, and is then included in one order-independent content-deduplication batch. Fetch or extraction failures remain candidate-local and are represented only by fixed safe failure codes. The assembly owns a deadline race around injected fetch/extraction implementations so a dependency that ignores its request deadline cannot stall the batch.

Only retained extractions enter the existing N4.1 deterministic ranker. Every ranked result receives an exact prefix citation verified against its normalized extracted evidence. A provenance record binds result and citation IDs back through observation, path, provider, source ordinal, raw-response hash, fetch receipt, source-body hash, extraction ID, and normalized-text hash. Every observation receives exactly one terminal candidate record, including deterministic candidate-limit and retained-but-unranked outcomes. The immutable report explicitly fixes `synthesisPerformed` to `false`.

## Explicit exclusions

- No provider-specific Brave/Common Crawl adapter, credential, live provider call, external fetch, archive object read, browser/JavaScript rendering, PDF/JSON/OCR extraction, model, synthesis, query expansion, database, queue, durable orchestration, HTTP route, payment, cloud, IAM, or remote deployment.
- Authority and relevance inputs use deterministic repository-local heuristics. They are transparent mechanics, not benchmark-calibrated quality claims.
- Prefix citations are exact and mechanically verifiable, but they are not claim selection, summarization, entailment, or a complete model-facing prompt-injection defense.
- Worker threads and assembly-owned deadlines bound local execution but do not constitute an OS sandbox or durable distributed cancellation.
- Candidate-level failure containment preserves accounting; it does not retry providers or guarantee a minimum evidence count.

## Rejected alternatives

- Rank adapter snippets without fetching/extracting content: rejected because citations would not bind to hash-receipted evidence bytes.
- Deduplicate only canonical URLs: rejected because mirrors and syndicated content require N4.4 content-level duplicate handling.
- Let injected transports define timeout behavior: rejected because a non-cooperative dependency could make the assembly unbounded.
- Drop failed, duplicate, limited, or unranked observations: rejected because every federated observation requires auditable terminal accounting.
- Synthesize an answer in the same ticket: rejected because untrusted retrieved data needs a separate model-facing security and citation-preservation boundary.
