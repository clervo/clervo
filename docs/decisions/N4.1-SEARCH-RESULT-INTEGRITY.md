# N4.1 search result integrity decision

Date: 2026-07-30

## Decision

The first advanced-search slice establishes deterministic result integrity before any live retrieval or synthesis is added. Search evidence carries source identity, original URL, retrieval/publication timestamps, exact retained evidence text, and bounded authority/relevance inputs. Only HTTP(S) URLs without embedded credentials are accepted.

URLs are canonicalized conservatively by removing fragments, default ports, known tracking parameters, and trailing non-root slashes while sorting remaining query parameters. Results with the same canonical URL collapse to one deterministic winner. This is exact URL deduplication only; semantic and near-duplicate content detection is not claimed until extraction supplies normalized content.

Ranking exposes integer freshness, authority, relevance, diversity, and total basis-point components. The weighting is deterministic: 30% freshness, 25% authority, 35% relevance, and 10% hostname diversity, with stable tie-breaking. Freshness uses an explicit age bucket based on `publishedAt` when present and `retrievedAt` otherwise. These are contract mechanics, not a claim that future provider-derived quality signals are calibrated.

Citations are accepted only when they identify a retained result, repeat its exact canonical URL, use valid character offsets, and quote the exact evidence substring at those offsets. Missing, truncated, URL-mismatched, or text-mismatched citations fail closed.

## Bounded preflight evidence

- Controlling-plan §7.1 requires URL normalization, near-duplicate removal, freshness/authority/relevance/diversity ranking, evidence-tied citations, deterministic schemas, and a citation verifier.
- Repository-local contracts require deterministic, strict, fail-closed behavior and do not yet provide search retrieval or extraction content.
- No external provider/tool survey was needed for this contract-only slice; retrieval tools and lawful supply are intentionally deferred to N4.2.

## Explicit exclusions

- No provider, search engine, crawler, browser, fetcher, extractor, model, database, queue, HTTP route, cache, payment, cloud, IAM, or deployment is used.
- No semantic or near-duplicate content removal, query rewriting, parallel/federated retrieval, JavaScript rendering, synthesis, language/region routing, or benchmark claim is made.
- No SSRF, robots, redirect, MIME, timeout, response-size, prompt-injection, or isolated-browser enforcement is claimed.
- Authority and relevance inputs are bounded contract fields, not yet independently measured or provider-qualified signals.

## Rejected alternatives

- Build synthesis before citation verification: rejected because generated prose must not outrun retained evidence.
- Treat result-limit truncation as deduplication: rejected because it would misstate search quality and coverage.
- Claim near-duplicate removal from URL equality: rejected because different URLs can contain the same content and one URL can change content over time.
- Use floating-point aggregate scores: rejected because integer components and basis points are easier to reproduce and audit.
