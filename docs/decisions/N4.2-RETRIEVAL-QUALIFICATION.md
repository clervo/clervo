# N4.2 retrieval qualification decision

Date: 2026-07-30

Status: provisional

## Decision

Provisionally select Brave Search API as the primary real-time retrieval path and Common Crawl URL Index plus WARC/WAT/WET objects as the archive fallback. They are independently operated failure domains. Selection is not qualification: both live route gates remain closed until evidence-dated terms, authentication, quota, response-contract, content-use, and failure-isolation checks pass.

The repository now defines an immutable two-path qualification snapshot and a fail-closed retrieval-target policy. Synthetic passing fixtures prove contract behavior only; they are not provider qualification evidence.

## Bounded preflight evidence

### Brave Search API

Official product material states that Brave provides real-time search data from its own independent Web index rather than repackaged Google or Bing results. It advertises URLs, text, news, images, optional LLM context, citations, and plan-specific request capacity.

Official restrictions reviewed:

- storing results in whole or in part requires a plan explicitly granting storage rights;
- the API does not grant rights to third-party webpages;
- customers following returned URLs remain responsible for publisher copyright terms.

The product page was reachable. Official developer and terms endpoints returned HTTP 403 in this environment, and no API credential was available. Authentication, quotas, error behavior, and response fields remain unverified.

### Common Crawl

Official material states that the corpus contains petabytes of raw pages, metadata, and text collected since 2008, searchable by URL Index and readable from AWS Open Data over S3 or HTTP(S). This is an independently operated archive path, not a real-time search substitute.

Official restrictions reviewed:

- the Terms of Use grant a limited service license, not blanket rights to third-party content;
- crawled content may carry separate publisher terms;
- users must comply with law and respect third-party rights;
- Common Crawl recommends legal review before commercial use;
- the service and content are provided “as is” and “as available.”

Terms and access documentation were reachable. No bounded URL Index plus byte-range archive read was performed, so practical schema, throttling, retry, and extraction behavior remain unverified.

## Qualification contract

Each selected path carries:

- provider/path identity, primary/fallback role, mechanism, and independent failure domain;
- `checkedAt` and `expiresAt` timestamps;
- terms state and explicit restriction acknowledgment;
- allowed content-use modes: search metadata, transient extraction, retained evidence, or archive replay;
- required evidence-dated checks for terms, authentication, quota, response contract, content use, and failure isolation;
- derived `routeEligible` and failure codes.

Exactly two selected paths with distinct failure domains and complete eligible checks are required for `twoPathGatePassed`.

## Retrieval safety boundary

The target policy rejects non-HTTP(S) URLs, embedded credentials, non-default ports, local/metadata hostnames, unresolved targets, loopback/private/link-local/carrier-grade-NAT/multicast addresses, unsafe redirect hops, redirect overflow, disallowed or unavailable robots policy, unsupported content use, unsupported MIME types, and oversized responses.

The pure contract does not claim network enforcement. N4.3 must implement DNS resolution, socket pinning or connection-time revalidation, streaming byte aborts, robots retrieval/cache, credentials, adapters, and isolated parsing. Every redirect must be revalidated. Archive replay may mark robots `not_applicable` but remains governed by provider and publisher terms.

## Requalification steps

1. Capture dated, hashed copies of the exact applicable terms and purchased plan.
2. Record legal/product approval for each content-use mode and retention duration.
3. Run a credentialed Brave request and record status, schema, request ID, quota headers, latency, and safe failure responses.
4. Run a bounded Common Crawl URL Index query and range read; record schema, archive timestamp, latency, retries, and extraction compatibility.
5. Probe malformed auth, throttling/429, timeout, and 5xx behavior without exposing secrets.
6. Exercise the real fetcher/parser against the SSRF, redirect, robots, MIME, and byte-limit corpus.
7. Use short qualification expiry; terms or plan changes invalidate qualification immediately.
