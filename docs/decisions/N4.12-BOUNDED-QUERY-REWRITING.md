# N4.12 bounded query rewriting decision

Date: 2026-07-30

## Decision

Use a deterministic, token-preserving rewrite policy with exactly two variants: normalized identity and escaped exact phrase. Do not use an LLM, synonyms, inferred entities, broadening terms, provider-specific operators, tools, or external state.

The rewrite plan is immutable, versioned, bounded to 2,000 characters and 64 tokens, and SHA-256 bound into the retrieval federation plan. Federation revalidates the embedded artifact and exact primary/fallback variant mapping before invoking adapters. The normalized original remains the operation, response, ranking, citation, and synthesis query identity.

## Consequences

- Existing qualification, deadline, parallelism, failure-isolation, and citation boundaries remain intact.
- The primary path receives identity; the fallback receives exact phrase. This deliberately supersedes N4.5's same-query-per-path rule while preserving one response query identity.
- This is repository evidence only. No live provider behavior, retrieval quality improvement, or staging operation is claimed.

## Rejected alternatives

- Model-generated expansions: rejected because they add cost, nondeterminism, prompt-injection exposure, and unsupported inference.
- Synonym/entity expansion: rejected because it can alter intent and introduce facts absent from the request.
- Provider-specific syntax: rejected because it couples the provider-neutral federation contract to provisional suppliers.
- Unbounded variant fan-out: rejected because it weakens cost, latency, and audit limits.
