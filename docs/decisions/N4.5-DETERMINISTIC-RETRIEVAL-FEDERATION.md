# N4.5 deterministic retrieval federation decision

Date: 2026-07-30

## Decision

Retrieval federation is a provider-neutral contract boundary, not a provider activation ticket. `createRetrievalQueryPlan` accepts one normalized identity query, a bounded absolute deadline, and a repository-local N4.2 qualification snapshot. It reconstructs the qualification decision at plan time, requires the exact two-path gate to remain open and unexpired, records primary/fallback executions in deterministic order, and binds the plan to the reconstructed qualification by SHA-256.

`runRetrievalFederation` requires that same qualification snapshot again and rejects substitution or forged plan metadata before invoking adapters. Both qualified paths start concurrently. They receive the same query, operation identity, absolute deadline, and independently linked abort signals. A path failure never cancels its peer; caller cancellation aborts both; elapsed or reached deadlines create explicit terminal records for both paths; and late adapter settlement cannot mutate a returned report.

Successful adapter responses are bounded to 100 candidates per path and converted into immutable observations carrying path/provider identity, source ordinal, retrieval time, and a canonical raw-response hash. Invalid candidate metadata fails only that path. Adapter exceptions and cancellation reasons are never serialized; reports use a fixed safe failure-code allowlist. Complete, partial, failed, and cancelled outcomes are derived from exactly two immutable attempt records rather than provider claims.

## Explicit exclusions

- No Brave or Common Crawl adapter, credential, live provider call, archive object read, query expansion, model, synthesis, ranking, citation assembly, fetch, extraction, database, queue, cache service, HTTP route, payment, cloud, IAM, or deployment.
- Qualification revalidation proves consistency with repository-local evidence only. Both live provider gates remain closed until their missing credentialed/index/range-read probes and content-use checks pass.
- Concurrent invocation does not claim equal provider latency, quality, freshness, availability, quota, or result coverage.
- Raw-response hashing binds JSON metadata supplied at the adapter boundary; it is not a network-byte receipt and does not replace N4.3 fetch receipts for retrieved content.
- The runner uses process-local timers and abort signals. Durable execution/recovery and distributed cancellation are not claimed.

## Rejected alternatives

- Sequentially invoke fallback after primary failure: rejected because it violates independent-path latency and prevents explicit parallel partial-failure accounting.
- Trust a previously constructed plan without the qualification snapshot: rejected because qualification substitution or stale evidence could cross the execution boundary unnoticed.
- Fail fast when either adapter rejects: rejected because one failure domain must not suppress evidence from the other.
- Serialize provider exception messages: rejected because messages may contain secrets, unstable vendor details, or unbounded cardinality.
- Merge, rank, fetch, extract, or synthesize candidates in this ticket: rejected because federation provenance and failure semantics require their own bounded acceptance gate.
