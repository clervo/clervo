# N3.1 observability and alert contract decision

Date: 2026-07-30

## Decision

Clervo uses repository-local, vendor-neutral contracts for structured log records, metric points, trace spans, and alert events. Construction is allowlist-first and fail-closed. Secret-bearing names are removed, secret-bearing values are replaced with `[REDACTED]`, control characters are normalized, and a redaction count creates a safe security signal without reproducing the rejected material.

Metrics have a smaller dimension allowlist than logs and spans. Operation, trace, span, request, payment, wallet, user, and arbitrary provider identifiers are forbidden as metric dimensions. Duration is recorded in seconds; integer event counts use unit `1`. Alert evaluation maps sanitized records to fixed codes, severities, summaries, and stable low-cardinality fingerprints. Alert delivery remains unimplemented.

## Bounded preflight evidence

- OWASP Logging Cheat Sheet, reviewed 2026-07-30: exclude or sanitize secrets and sensitive data; sanitize event data to prevent log injection; verify logging failures do not prevent the application from running or leak information; protect log availability; integrate serious-event alerting with responsible teams.
- OpenTelemetry semantic conventions 1.43.0, reviewed 2026-07-30: use consistent semantic attribute names; keep metric names and attributes understandable and unambiguous; aggregations across attributes should remain meaningful; durations should use seconds; integer counts should use UCUM annotations or unit `1` as applicable.
- Repository-local audit contract: retain its narrow append-only evidence role. Runtime telemetry is a separate contract and does not widen audit facts into arbitrary diagnostic payloads.

## Explicit exclusions

- No raw request/response body, exception object, stack trace, provider payload, payment payload, credential, signature, session, wallet secret, or authorization header is accepted.
- No arbitrary attribute map or user-selected alert summary is accepted.
- No remote exporter, telemetry backend, paging vendor, dashboard, SLO claim, retention policy, or delivered-alert claim is implemented.
- No product execution, provider, wallet, facilitator, cloud, IAM, deployment, or payment mutation is performed by this ticket.

## Rejected alternatives

- Reusing audit events for all observability: rejected because runtime diagnostics and immutable business evidence have different retention, volume, cardinality, and access concerns.
- Silent acceptance of unknown fields: rejected because future callers could accidentally export secrets or high-cardinality values.
- Dynamic alert text copied from logs: rejected because it can leak untrusted upstream content and defeat stable grouping.
- Correlation IDs as metric dimensions: rejected because they create unbounded time-series cardinality.
