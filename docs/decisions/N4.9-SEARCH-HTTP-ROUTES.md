# N4.9 bounded search HTTP route decision

Date: 2026-07-30

## Decision

Expose the completed repository-local search contract through two bounded `POST` paths: `/v1/search/free` and `/v1/search/paid`. Both accept the same strict JSON body and mandatory `Idempotency-Key`, bind canonical requests to deterministic operation IDs and SHA-256 fingerprints, reject query parameters and unknown body fields, and validate executor output against operation/query/result/citation boundaries before returning it.

The free route uses a small injectable quota interface with a process-local reference implementation. Replays return the stored result without consuming quota or invoking the executor again. The paid route returns the existing N2.1 explicitly non-payable mock x402 challenge by default. A mock-paid completion path exists only behind constructor dependency injection for repository-local tests and passes through the existing N2.2 verification, execution, settlement, ledger, and receipt kernel.

Discovery advances from `contract_preview` to `implemented_unverified`: it publishes only `search.query`, the two exact paths, request/result schemas, and explicit limitations. It does not claim public deployment, real payment verification, facilitator configuration, authorization, settlement, or production readiness.

## Explicit exclusions

- The HTTP adapter is a Node.js server factory with an injected `SearchExecutor`; this ticket does not select or wire a live Brave, Common Crawl, browser, or model provider.
- The process-local quota and idempotency map are reference mechanics, not horizontally durable production enforcement.
- The default paid path never accepts a payment signature and never executes. Test-only mock completion is not a public payment capability.
- No public listener, DNS, TLS, database, queue, cloud, IAM, deployment, wallet, facilitator, external traffic, or USDC spend is introduced.

## Rejected alternatives

- Combine free and paid behavior behind a query/header switch: rejected because the funding boundary must be explicit and separately discoverable.
- Execute after any payment-looking header: rejected because only the injected mock seam may reach N2.2 and exact quote/request/amount verification must precede execution.
- Trust executor output: rejected because operation/query/result limits and exact citation bindings must be revalidated at the HTTP boundary.
- Advertise a live or payable service: rejected because repository-local loopback tests do not prove public deployment or real x402 readiness.
