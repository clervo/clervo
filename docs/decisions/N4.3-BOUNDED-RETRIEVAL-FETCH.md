# N4.3 bounded retrieval/fetch decision

Date: 2026-07-30

## Decision

The first live-byte retrieval boundary is a provider-neutral `fetchRetrieval` function. Callers supply a URL, content-use mode, provider-granted modes, byte ceiling, absolute deadline, and visible user agent. DNS and transport are injectable for deterministic tests; the default Node.js transport pins the selected public address through `lookup` and rejects a response whose connected socket address differs.

Every robots or content hop is independently URL-validated, DNS-resolved, public-address checked, address-pinned, and receipt-recorded. Cross-origin redirects trigger robots evaluation for the new origin before content traffic. Redirects are bounded. A single absolute deadline covers DNS, connection establishment, redirect processing, body streaming, and hashing. Declared and streamed sizes are bounded, and partial bodies are never returned after rejection.

Robots policy fails closed when unavailable or disallowing. Matching uses case-insensitive product-token selection, only the longest matching non-wildcard user-agent specificity, percent-decoding of unreserved octets, longest normalized matching rule, and allow-on-equal-specificity. Cached entries carry fetch and expiry evidence. Explicit `not_applicable` is accepted only for `archive_replay`; it is not permission to retain or republish content.

Successful receipts bind the final URL, network hops, robots decisions, MIME type, byte length, and SHA-256 digest. Rejected receipts preserve already-issued hop evidence and a stable failure code. Receipts and nested arrays/objects are frozen.

## Bounded qualification observation

One non-billable request to the public Common Crawl collection metadata endpoint was executed with a 5-second connect timeout, 15-second total timeout, 256 KiB download ceiling, and captured digest. It returned HTTP 200, 34,675 bytes, and SHA-256 `eac053eb9d810c1ca519c99e7fdcf3c24a8042809becbbf6c6854a5795c1d52a` from `https://index.commoncrawl.org/collinfo.json`.

This is a reachability observation, not route qualification. It did not query the URL Index, select a capture, issue an archive byte-range read, validate extraction, exercise throttling/retry behavior, or establish content-use approval. Common Crawl and Brave route gates remain closed.

## Explicit exclusions

- No provider-specific search adapter, credential, quota handling, live route activation, browser, parser, JavaScript execution, database, queue, cache service, HTTP product route, payment, cloud, IAM, or deployment.
- MIME allowlisting does not make active HTML/PDF safe to parse; isolated extraction remains mandatory.
- The in-memory robots cache is process-local and not a durable distributed policy store.
- DNS pinning and remote-address equality protect this adapter path but do not replace deployment-level egress controls.
- No claim of RFC-complete robots implementation, retrieval quality, freshness, availability, or legal permission beyond recorded provider/publisher terms.

## Rejected alternatives

- Resolve once and let the HTTP client resolve again: rejected because DNS rebinding could bypass the validated address.
- Validate only the initial URL: rejected because redirects can cross into private or separately governed origins.
- Treat robots failure as allow: rejected because policy uncertainty must fail closed.
- Buffer without an aborting stream ceiling: rejected because declared lengths are optional and untrusted.
- Begin extraction/synthesis in the fetch ticket: rejected because active-content isolation and normalized evidence require their own bounded acceptance gate.
