# N4.10 recorded search pipeline decision

Date: 2026-07-30

## Decision

Add a typed repository-local `RecordedSearchExecutor` under `services/search` and inject it into the existing N4.9 HTTP server. The executor builds an evidence-dated two-path qualification snapshot, runs the same normalized query through two independent recorded adapter boundaries, sends their public-looking recorded URLs through the real bounded fetch implementation using injected transport responses, performs real worker-thread extraction and content deduplication, assembles deterministic ranked results and exact citations, and optionally crosses the N4.7 no-tools/no-actions synthesis boundary with a deterministic recorded adapter.

The HTTP server now awaits asynchronous executors for both free and explicit test-only mock-paid requests. Identical concurrent requests sharing an idempotency key await one in-flight promise, so the executor and free quota are consumed once. The mock-commerce kernel retains its existing synchronous API and adds a separate asynchronous method for the injected test seam; execution failures release claimed process-local mock payment and settlement identifiers before any settlement, ledger transaction, or receipt exists.

## Explicit exclusions

- Recorded adapter responses and transport bytes are repository-local fixtures. They do not qualify Brave, Common Crawl, a model, or any other live supplier.
- The injected transport performs no DNS or network traffic. Loopback HTTP is the only socket traffic exercised.
- The default paid route remains non-payable and never executes from a payment-looking header. The asynchronous paid completion path remains constructor-injected and test-only.
- Process-local idempotency, quota, mock commerce, and recorded qualification are not durable or horizontally distributed production controls.
- No public listener, DNS, TLS, database, queue, browser, credential, cloud/IAM mutation, facilitator, wallet, real payment, or USDC spend is introduced.

## Rejected alternatives

- Return a prebuilt `SearchResponse`: rejected because it would not prove N4.2–N4.7 composition.
- Stub successful fetch/extraction receipts: rejected because N4.10 must exercise the actual bounded fetch and worker extraction implementations.
- Place orchestration in `packages/contracts`: rejected because the recorded executor is a search-service implementation, not a shared contract.
- Select live providers while wiring the executor: rejected because live qualification and Stage 4 staging exit evidence require a separately authorized bounded ticket.
- Keep the mock-paid executor synchronous: rejected because the complete retrieval pipeline is inherently asynchronous.
