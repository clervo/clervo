# N4.27R search generalization, live-route and browser repair

N4.27R completed its controlled repair-entry gates. This is not a commercial, production, Exa-parity, reference-pattern, advanced-search or Stage 5 qualification. The source-bound Stage 4 blocker count remains 10 because this ticket did not deploy the repair to staging, did not complete connected-cache/upstream-locale proof, and was prohibited from running mock x402 or payment.

## Root causes

The read-only ledger classifies all 50 original balanced tasks without rerunning the frozen N4.27 holdout. Forty-eight failed. Thirty labelled sources were entirely absent from returned candidates, 11 controlled fixture URLs were never connected to retrieval, four answerable tasks returned no candidates, and three no-result tasks emitted false positives. Only two no-result tasks passed. No answerable task returned a labelled URL, so answerable recall and precision were both zero; the published 0.04 values came from the two correct no-result cases.

The N4.26 regression appeared stronger because its corpus was aligned to the narrow Wikipedia/Crossref seed set and its relevance predicate accepted generic expected-term overlap without URL qrels. N4.27 instead required labelled URL prefixes plus all evidence terms across unseen domains and disconnected fixtures. That is a corpus/evaluator alignment problem, not proof of generalized retrieval.

Four evaluator defects were independently proven and corrected only in the new N4.27R evaluator:

- correct no-result accuracy was incorrectly folded into recall and precision;
- correct empty no-result output was given an artificial nonempty ideal rank list and therefore zero nDCG/MRR;
- combined “baseline victory” could be awarded by citation/structure weights without retrieval improvement;
- missing locale response fields automatically received full locale credit.

URL-prefix normalization and expected-term strictness were rejected as causes of the collapse because no labelled URL reached either final predicate. Correcting them would not have changed an answerable outcome. The old extraction rate of 0.92 largely reflected four answerable zero-candidate tasks rather than extraction failures over returned pages.

Latency and live-route degradation had two concrete causes: empty search results counted as operational circuit failures, producing 32 `live_federation_circuit_open` attempts, and the outer deadline could return without joining abandoned route work, allowing later sequential requests to inherit background load. The old balanced artifact consequently recorded durations as high as 6785.670 ms despite a nominal 1800 ms route deadline.

## Ranking and coverage repairs

- Candidate rank is tracked per route and adapter rather than by arrival URL order.
- Hyphenated/dotted identifiers remain intact during lexical matching.
- A deterministic lexical relevance floor runs before authority, freshness, RRF or diversity can promote a weak candidate.
- RRF uses the standard `k=60` reciprocal contribution and exposes its component.
- Candidate-flow records now expose source rank, lexical relevance, RRF contribution and final disposition (`ranked`, relevance floor, exact duplicate, near duplicate or limit).
- Near-duplicate suppression remains same-host only and preserves distinct sellers, offers, locations, versions and evidence.
- Valid empty routes remain operational successes, enabling honest empty results instead of poisoning circuits or forcing HTTP 503.
- No query ID, qrel, expected URL or answer term is read by production ranking.

## Live route

The controlled repair runtime uses six zero-provider-cost source classes: approved official feeds, public catalog endpoints, government open data, official corporate disclosures, open research registries and public developer registries. Each adapter has its own health/circuit identity, hard deadline, suspension state and quota. Discovery merges round-robin, caller cancellation propagates, empty success does not open the circuit, and one suspended source cannot hold the combined route hostage. Public shared SearXNG, paid/eventually-paid general-Web providers and closed-platform bypasses remain absent.

Development live recall was 0.4444, precision 1.0000 and p95 4.109 ms in the controlled runtime. Live supplied a relevant unique result for 15/15 focused misses. The largest adapter share was 0.20. These adapters are controlled repair fixtures and source-class qualifications; only the pre-existing Wikimedia/Crossref adapters exist in the production code path, so production source deployment is explicitly not qualified.

## Browser and hostile security proof

The repair retained the N4.27 digest-bound gateway/default-deny design and removed the flaky public fixture dependency. A controlled certificate-pinned HTTPS fixture and real Chromium process completed 20 consecutive startups and 20 clean teardowns with zero orphans or retained state. Twenty JavaScript fixtures passed; p95 was 910.016 ms. The worker ran as UID 65534 with ephemeral profiles, gateway-only networking, no login/cookies/downloads/caller scripts/stealth/proxy rotation and a 5.5-second process deadline.

Controlled loopback, private, link-local, metadata, IPv6 loopback, redirect-to-private and DNS-rebinding denials passed. Robots, MIME, decompression and output limits passed. Eight hostile pages attempted to change routing, ranking, payment, tools, citations, secrets and system policy; all remained untrusted evidence and changed no policy state. Stopped-runtime availability was honestly unavailable. This is controlled local repair qualification bound to the prior staging design, not a replacement for the still-required deployed staging proof.
