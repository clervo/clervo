## Security architecture

The Crawl4AI worker is a one-page disposable execution plane behind `clervo.search.crawl4ai-isolation.v1`. It has no Service/ingress and default-deny egress except to the internal retrieval-authorization gateway on TCP 8443. The browser cannot resolve/connect directly. The gateway must validate each document/asset URL, every DNS answer, the pinned connected address, and each redirect. The pod specification denies host namespaces/mounts/sockets, service-account token, privilege escalation, Linux capabilities, persistent storage, metadata/control-plane/database/commerce-secret access, and uses non-root identity, read-only root, memory-backed bounded state, seccomp, CPU/memory/disk/file/process limits, one browser page, bounded output/network/execution, deterministic teardown, orphan reap, and kill switch.

The executable TypeScript boundary refuses work without exact Crawl4AI/Playwright/worker/runtime attestation, accepts only HTTP(S) Clervo-approved targets, freezes a no-hooks/no-download/no-session/no-login/no-cookie/no-CAPTCHA/no-proxy/no-stealth capability set, reduces worker errors to safe codes, terminates on crash/deadline/cancellation/limit violation, checks state removal and zero orphans, and rejects new work after the kill switch.

## Retrieval and cache proof

- Static and browser targets deny unsupported protocols/file URLs, URL credentials, literal IPs, loopback/private/link-local/metadata targets, IPv4-mapped/unique-local/link-local/loopback IPv6, unsafe DNS answers, connected-address rebinding, and private redirects.
- Robots is mandatory for current pages; disallow prevents content fetch. Applicable `Crawl-delay` is parsed and shared per-domain concurrency/delay is enforced. Only explicit User-Agent/Accept/Accept-Encoding headers are sent; auth and cookies are absent.
- Gzip/deflate/Brotli compressed bytes and decompressed bytes have separate ceilings. MIME is checked before body use; streaming, output, deadline, cancellation, page/process/memory/disk/network limits fail atomically.
- Cache keys bind canonical URL, exact route, and policy. Environment-separated filesystem and PostgreSQL stores preserve checksum-bound bodies/timestamps. Poisoned records evict; route mismatch misses; forced refresh, exact eviction, URL removal, and denylist removal work. Stale content is available only within the bounded degraded window with fetched-at, expires-at, age, and `stale_while_degraded=true` visible.
- Cache records have no fields for customers, queries, secrets, wallets, cookies, or browser state and reject non-false safety declarations. The repository cannot prove that arbitrary page bodies never contain secret-looking public text; admission still relies on upstream source policy and the explicit cache material boundary.
