# N4.13 — Implement isolated JavaScript retrieval

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can JavaScript-rendered HTML be retrieved through a bounded browser boundary without bypassing N4.3 preflight safety, allowing unrestricted browser egress, persisting browser state, or exposing renderer internals?
- **Inputs allowed:** a fresh successful robots-allowed N4.3 fetch receipt, bounded render policy, injected adapter, core DNS resolver, timestamps, and cancellation signal. No external network, installed browser dependency, cloud/IAM mutation, deployment, payment, or USDC spend.
- **Freshness date:** 2026-07-31.
- **Secrets involved:** none.

## Decision

Require static preflight before an injected disposable browser-process adapter. Core code authorizes each same-origin request only after public-address resolution, enforces request/network/rendered-byte limits and one absolute deadline, validates exact request and connected-address attestations, requires a fixed isolation attestation, and releases bytes only with an immutable hash-bound success receipt.

## Validation contract

- **Focused test:** `npm run test:n4.13`.
- **Failure test:** missing/stale/non-HTML/robots-bypassed preflight, cross-origin/private/rebound/hidden requests, forged isolation, unsafe final origin/MIME, byte overflow, deadline, cancellation, invalid headers/limits, and secret-bearing adapter errors fail closed.
- **Acceptance:** canonical repository acceptance, staging loopback smoke, boundary verification, secret scan, and diff checks.
- **Cost/network effects:** no external traffic and 0 USDC spent.
