# N0.3 — Establish CI, secret scanning, environments, and staging

## Ticket

- **Stage:** 0 — Clean-room foundation
- **One question:** Can Clervo enforce a reproducible pre-merge gate and a distinct staging release boundary without leaking secrets or confusing local readiness with live deployment?
- **Why it blocks the stage:** Contract and commerce work cannot proceed safely without automated acceptance, credential-leak prevention, and explicit development/test/staging/production separation.
- **Inputs allowed:** controlling plan; N0.1/N0.2 repository decisions; official GitHub Actions/environment/security documentation; maintained public action releases; local Git/tool/credential metadata. No legacy implementation or state.
- **Preflight scope:** CI workflow security, action maintenance/licensing, secret handling, environment protection semantics, local runtime availability, Git remote state, and deployment capability.
- **Research limit:** bounded to the current session.
- **Freshness date:** 2026-07-29.
- **Secrets involved:** environment-variable names and tool presence only; no values inspected, logged, copied, or used.

## Decision

Establish GitHub Actions as the portable CI contract, a repository-native scanner for committable files and Git history, four non-secret environment descriptors with unique database/queue/secret boundaries, and a protected-environment staging readiness workflow. Add a minimal hello service and rollback manifest to prove health/smoke semantics locally. Defer live deployment because no remote or authorized hosting control plane exists.

- Immutable-SHA-pinned CI and staging-readiness workflows with read-only token permissions.
- Weekly Dependabot checks for npm and GitHub Actions pins.
- Zero-dependency secret scanner with redacted findings and injected-secret failure coverage.
- Development, test, staging, and production environment descriptors plus safe `.env.example`.
- Minimal hello service, staging smoke test, release manifest, and rollback contract.
- ADR-0003, operations guide, acceptance tests, journal evidence, and updated handoff.

## Validation contract

- **Focused tests:** clean `npm ci`; environment invariants; secret scan of working tree/history; workflow pin/permission assertions; staging `/healthz`, `/hello`, and 404 probes; clean-room and stack verifiers.
- **Failure test:** create a temporary committable file containing a credential-shaped assigned secret; the scanner must fail without printing the matched value; remove it and pass cleanly.
- **Acceptance command:** `npm test` under the selected Node.js 24 runtime, plus `npm run staging:smoke`.
- **Cost/network effects:** read-only GitHub documentation/API/Git tag and npm registry requests during research/install; loopback HTTP during staging smoke; no provider/cloud/IAM/deployment mutations or payments; 0 USDC.
- **Evidence produced:** workflows, scanner, failure test, environment descriptors/verifier, hello service/smoke test, release manifest, ADR, operations guide, ticket, journal, and handoff.
- **Parking lot:** remote repository creation; observed CI run and branch protection; protected GitHub environment configuration; hosting/provider selection; live URL, traffic switch, and rollback; PostgreSQL provisioning/migrations/backups; formatting/lint framework; database/queue integration.
- **Stop condition:** local acceptance/failure tests pass, evidence is committed, handoff names N1.1, then stop.
