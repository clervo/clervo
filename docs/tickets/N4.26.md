# N4.26 — Live staging quality, monitoring, budgets, and traffic stops

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can the real Clervo Search system operate in isolated
  staging, produce commercially useful and evidence-backed Live Intelligence
  results, disclose economic infrastructure cost, deliver operational alerts,
  and stop traffic before an unbounded or dishonest result reaches a customer?
- **Freshness date:** 2026-07-31.
- **Payment:** mock only; route non-payable; 0 USDC.
- **Third-party general-Web production provider cost:** USD `0.000000`.

## Decision

The staging system produced useful evidence-backed results, exercised both
independent retrieval identities, delivered the primary email alert path, and
failed closed under bounded route, quota, circuit, cost and global-traffic
drills. It is **not yet commercially competitive** and Search is not the
reference pattern. Eleven of the 21 starting Stage 4 blockers have hash-bound
staging evidence; ten remain.

The advanced marketing claim is not authorized. Browser runtime attestation,
the complete staging security suite, connected read-through cache proof,
upstream locale honoring, named baseline improvement, complete cost controls,
and payable commerce remain open. Stage 5 remains unauthorized.

## Build and proof output

- Versioned 50-task corpus: ten tasks in each of the five authorized solution
  families, including connector lifecycle, hostile/no-result, stale,
  JavaScript-required, locale and degradation cases.
- Reproducible evaluator and compressed raw results for 182 executions across
  focused, live, simple-combination, combined and connector-lifecycle paths.
- Focused/live/simple/combined scorecard plus bounded SearXNG observation;
  unavailable Firecrawl and paid baselines remain explicitly unavailable.
- Isolated GKE staging deployment using only new `clervo-n426-*` resources,
  immutable images, ClusterIP services, default-deny policies, persistent
  cache/index storage, fixed quota and mock-only payment state.
- Delivered owner-email channel request, queryable critical-event metric,
  bound alert policy, redacted operational events, and explicit missing
  Telegram route.
- Economic cost model, USD 10 ticket budget, USD 5/day ceiling, operation
  ceilings, candidate price floors, route/circuit/quota/cache/kill-switch
  drills, and cleanup verification.

## External and resource failures

The preferred isolated project was created but could not be linked to billing
because the billing account project quota was reached. Execution therefore
used only newly named `clervo-n426-*` resources in the already authenticated
project without touching legacy resources.

The browser path failed twice: namespace CPU quota rejected the first attempt
before pod creation, and the second expired while pulling the pinned image.
Per the two-failure rule it was disabled; no runtime attestation is claimed.
The qualified Telegram route was absent. Paid comparison entitlements and the
open-source Firecrawl runtime were unavailable and were not purchased.

## Cleanup and stop

After evidence capture, `clervo-n426-staging`, its node workload, the
`clervo-n426-staging-data` disk, and the local port-forward were removed.
Digest evidence, the USD 10 budget, email channel, alert policy, log metric,
Artifact Registry, and empty unbilled project remain. Active compute exposure
is USD 0/day; retained artifact/logging storage is bounded in the evidence at
an estimated USD 0.01/day upper bound.

Commit N4.26 atomically and stop. N4.27 is the exact next ticket only after
separate payment authority. Do not begin N4.27, N4.28, Stage 5, AI, Sandbox,
real settlement, or USDC spending in this ticket.
