# N0.2 — Select runtime, database, and queue

## Ticket

- **Stage:** 0 — Clean-room foundation
- **One question:** Which runtime, authoritative database, and durable queue give Clervo the smallest credible foundation for transactional commerce and asynchronous provider execution?
- **Why it blocks the stage:** Lockfiles, tests, application contracts, local environments, CI, and staging cannot be made reproducible without a selected stack.
- **Inputs allowed:** controlling master plan; N0.1 boundary; official runtime/database/tool documentation; maintained public repositories; public package metadata; local tool and container availability. Legacy implementation code and state were not inputs.
- **Preflight scope:** standards, release/support policies, repositories, queue semantics, transaction/idempotency primitives, licenses, integration cost, security, and local reproducibility.
- **Research limit:** bounded two-hour decision.
- **Freshness date:** 2026-07-29.
- **Secrets involved:** environment variable names were inventoried without values; no credential was used.

## Candidates and evidence

The detailed evidence and ten considered alternatives are recorded in ADR-0002. Primary candidates were Node.js/TypeScript, Python, Go, and Rust; PostgreSQL and SQLite; pg-boss, BullMQ/Redis, Temporal, PGMQ, and a custom PostgreSQL queue.

Maintenance and licensing checks found supported Node 24 LTS and PostgreSQL 18 lines, active pg-boss 12.26.x releases, and permissive licenses for the selected direct tools. The local host has Node 22/npm but no Docker, PostgreSQL client, or container runtime, so N0.2 can validate metadata and dependency resolution but cannot honestly claim a running database or queue.

## Decision

Select TypeScript 7 on Node.js 24 LTS with ESM and npm; PostgreSQL 18 as the authoritative store; and pg-boss 12 on the same PostgreSQL cluster as the durable queue. Pin the current reproducible versions in repository metadata and enforce consistency locally. Do not provision or implement application behavior in this ticket.

## Completion

- **Result:** accepted. TypeScript 7.0.2 on Node.js 24.18.1, PostgreSQL 18.4, pg-boss 12.26.3, and npm 10.9.8 are selected and pinned. This is an architecture/tooling decision, not a claim that PostgreSQL or pg-boss is running.
- **Files changed:** `.nvmrc`; `package.json`; `package-lock.json`; `infra/stack-versions.env`; `scripts/verify-stack-decision.mjs`; `scripts/verify-clean-room-boundary.sh`; `docs/decisions/ADR-0002-runtime-database-and-queue.md`; `docs/tickets/N0.2.md`; `docs/journal/BUILD-JOURNAL.md`; `README.md`.
- **Tests and exact result:** clean `npm ci --ignore-scripts --no-audit --no-fund` installed 25 packages under Node.js 24.18.1; TypeScript reported `Version 7.0.2`; `npm ls --all` resolved pg-boss 12.26.3 and the expected optional platform/native packages remained optional; `npm audit --omit=dev --audit-level=high` reported `found 0 vulnerabilities`; `npm test` passed both boundary and stack checks under Node.js 24.18.1; an injected `POSTGRES_MAJOR=17` failed with exit 1 and `database must remain PostgreSQL 18`; an escaping source-tree symlink failed with exit 1 and `symlinks are forbidden`; both verifiers passed after restoration; `git diff --check` passed.
- **Deployment checked:** not applicable; N0.2 authorizes no deployment.
- **Claims still unknown:** running PostgreSQL/pg-boss behavior, application contracts, CI/staging, provider state, payment behavior, and production behavior.
