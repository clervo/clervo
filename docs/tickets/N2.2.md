# N2.2 — Build ledger, mock settlement, replay, and reconciliation

## Ticket

- **Stage:** 2 — Commerce core
- **One question:** Can Clervo complete one quote-bound mock-paid operation with exactly one execution and balanced charge, replay it without duplication, and quarantine/reconcile unknown settlement evidence without guessing?
- **Why it blocks the stage:** No product path may advance toward real payment until duplicate charge/execution prevention, balanced accounting, and unknown-outcome recovery are executable invariants.
- **Inputs allowed:** controlling plan; N1.1/N1.2 operation, idempotency, receipt, and audit contracts; N2.1 quote/mock challenge; repository conventions. No legacy runtime, wallet, facilitator, provider, database, or external payment.
- **Preflight scope:** authorization binding, deterministic mock settlement, append-only balanced postings, replay/conflict, quarantine, and reconciliation.
- **Research limit:** repository-local contract review only; no external research was required.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Add a deterministic in-memory mock commerce kernel with injected execution and settlement functions. It verifies only explicit mock payment evidence, seals authorization/settlement/ledger records, completes one immutable receipt, replays stored results, and quarantines unknown settlement until definitive hash-bound evidence reconciles the same authorization and settlement ID.

## Build output

- Mock authorization, settlement, ledger, paid-flow, replay, quarantine, and reconciliation TypeScript contracts.
- Three strict Draft 2020-12 schemas and six positive/negative fixtures.
- Eight focused adversarial tests covering complete flow, replay, conflict, cross-key payment reuse, payment rejection, unknown quarantine, definitive reconciliation, and tampered evidence.
- ADR-0008, ticket evidence, journal/README updates, generated schema/OpenAPI refresh, and next-ticket handoff.

- **Focused tests:** build and `npm run test:n2.2`; strict schema/fixture validation through `npm run contracts`.
- **Failure test:** changed request, expired/tampered/over-ceiling/non-mock payment, unknown settlement retry, or tampered/mismatched reconciliation evidence must not execute or post a duplicate charge.
- **Acceptance command:** `npm test` plus `npm run staging:smoke`.
- **Cost/network effects:** local tests only; no wallet, facilitator, provider, cloud, IAM, deployment, or payment mutation; 0 USDC.
- **Evidence produced:** source, schemas, fixtures, tests, generated artifacts, ADR, ticket, journal, README, and controlling handoff.
- **Parking lot:** PostgreSQL persistence/transactions, pg-boss recovery, HTTP paid flow, alert delivery, real PaymentPayload/signature verification, real facilitator/settlement, provider execution, and remote staging.
- **Stop condition:** focused and full acceptance pass, evidence is committed, handoff names N3.1, then stop.
