# N4.15 — Implement language and region options

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can callers select canonical language and region preferences that remain bound to request identity, cache identity, retrieval execution, assembly, and public output without claiming unverified provider behavior?
- **Inputs allowed:** search request fields, existing recorded adapters, deterministic contract/hash functions, strict schemas, and repository-local tests. No external provider, browser, cloud/IAM mutation, payment, or USDC spend.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Add provider-neutral `language` and `region` options with deterministic `en`/`US` defaults. Require already-canonical BCP 47 language tags and recognized uppercase two-letter regions. Bind both fields into HTTP and cache request identity, propagate them through the two-path recorded pipeline, disclose them in every search response, and reject output substitution.

## Validation contract

- **Focused test:** `npm run test:n4.15`.
- **Failure test:** non-canonical language, underscore tags, lowercase/unknown/pseudo regions, request/cache identity collisions, response/cache substitution, and executor output locale drift fail closed.
- **Acceptance:** canonical repository acceptance, schema/discovery generation, Stage 4 recomputation, staging loopback smoke, boundary verification, secret scan, and diff checks.
- **Cost/network effects:** no external traffic and 0 USDC spent.

## Completion

- **Result:** language and region options are repository-verified through the recorded pipeline and public response contract; live provider support and staging behavior remain unverified.
- **Focused validation:** `npm run test:n4.15` passed 6/6.
- **Canonical validation:** acceptance passed 161/161 with 32 strict schemas and 61 fixtures under Node.js 24.18.1/npm 10.9.8. Loopback staging smoke, clean-room boundary, working-tree/full-history secret scan, discovery generation, Stage 4 recomputation, and diff checks passed.
- **Stage effect:** `language_and_region_options` advances from `missing` to `repository_verified`, but remains `stagingVerified=false`; Stage 4 remains blocked.
