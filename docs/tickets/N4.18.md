# N4.18 — Prepare and attempt isolated GCP staging deployment

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can the bounded recorded search slice be packaged for an isolated Cloud Run staging service and can a fresh deployment be inspected, deployed, smoked, evidenced, and rolled back without touching existing workloads or enabling mock-paid execution?
- **Authorized target:** GCP project `bloxsniper-prod`, region `us-central1`, new isolated service `clervo-stage4-slice-staging` only.
- **Freshness date:** 2026-07-31.
- **Secrets involved:** GCP operator authentication, if available outside Git.

## Decision

Package the existing recorded executor behind a Cloud Run-compatible entry point. Expose `/healthz`, the bounded free sample, and the existing paid challenge route. Keep `allowMockPaidExecution=false`; do not claim a payable route, live retrieval suppliers, delivered telemetry, or remote rollback until fresh evidence exists.

The operator script pins the exact authorized project, region, and isolated service; requires an authenticated `gcloud`; caps the service at one instance; records the previous revision before deployment; runs the live smoke collector; and supports traffic rollback to the saved revision.

## Attempt result

The execution environment had `GCP_PROJECT=bloxsniper-prod` and `GCP_REGION=us-central1`, but no `gcloud`, application-default credential file, metadata identity, container builder, or usable browser control plane. The attempt therefore stopped before control-plane inspection or mutation. Zero resources were created or modified, zero billable provider calls were made, and zero USDC was spent. See `infra/staging/n4.18-attempt-evidence.json`.
