# N4.18 — Deploy and verify the isolated GCP staging slice

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can the bounded recorded search slice be packaged for an isolated Cloud Run staging service and can a fresh deployment be inspected, deployed, smoked, evidenced, and rolled back without touching existing workloads or enabling mock-paid execution?
- **Authorized target:** GCP project `bloxsniper-prod`, region `us-central1`, new isolated service `clervo-stage4-slice-staging` only.
- **Freshness date:** 2026-07-31.
- **Secrets involved:** GCP operator authentication, if available outside Git.

## Decision

Package the existing recorded executor behind a Cloud Run-compatible entry point. Expose `/v1/health`, the bounded free sample, and the existing paid challenge route. Keep `allowMockPaidExecution=false`; do not claim a payable route, live retrieval suppliers, delivered monitoring/alerts, or real settlement without fresh evidence.

The operator script pins the exact authorized project, region, and isolated service; requires an authenticated `gcloud`; caps the service at one instance; records the previous revision before deployment; runs the authenticated live smoke collector; and either restores the saved revision or deletes a first deployment.

## Deployment result

An authorized GCE operator path deployed immutable release `2f6fd6c` to private Cloud Run service `clervo-stage4-slice-staging`, revision `clervo-stage4-slice-staging-00001-7fn`. Cloud Build `52167bac-b84b-4533-b400-1a4769e87b11` completed successfully and produced image digest `sha256:16bcfbf77f874c0e323a67b18712df4d92318b71227838de141a0bbca0e72354`.

Authenticated remote smoke returned `200` from `/v1/health`, `200` from the bounded recorded `/v1/search/free` sample, and the required non-payable `402` challenge from `/v1/search/paid` with `executionAllowed=false`. Cloud Run request logs independently record those three responses. The service remains private, recorded-only, limited to one instance, and configured with paid execution disabled. No external retrieval provider was called, no real payment occurred, and 0 USDC was spent. See `infra/staging/n4.18-deployment-evidence.json` and `infra/staging/live-smoke-evidence-2f6fd6c.json`.

Rollback was exercised on the preceding isolated first deployment and deleted it successfully; the final release again captured an empty previous-revision state, so its scripted rollback mode is deletion of the ticket-owned service. The final verified service was intentionally left running for staging use.
