# N0.1 — Create the clean-room repository and prove zero old-runtime dependencies

## Ticket

- **Stage:** 0 — Clean-room foundation
- **One question:** Can Clervo begin in an independent repository with an enforceable boundary against the old runtime?
- **Why it blocks the stage:** Every later architecture, commerce, provider, and deployment decision would be contaminated if it inherited legacy code or state.
- **Inputs allowed:** controlling master plan; Git and filesystem metadata; legacy repository names and paths for deny-list verification only.
- **Preflight scope:** repository boundaries, Git isolation, filesystem links, and local dependency forms.
- **Research limit:** bounded to the current session.
- **Freshness date:** 2026-07-29.
- **License/terms/security review:** no third-party code or dependency was added. The verifier uses local POSIX tools and Git. No secret values were inspected.

## Decision

Create `/workspace/clervo-next` as a standalone Git repository. Track the required architecture skeleton and written clean-room policy. Enforce mechanically detectable boundary violations with a repository-local shell verifier. Defer all stack and infrastructure choices to N0.2 and N0.3.

## Build output

- Independent Git repository.
- Mandatory clean architecture directories.
- Repository instructions and ADR.
- Append-only build journal.
- Executable clean-room boundary verifier.

## Validation contract

- **Focused test:** `./scripts/verify-clean-room-boundary.sh` succeeds on the repository.
- **Failure test:** add a temporary symlink escaping the repository; the verifier must reject it; remove the symlink and re-run successfully.
- **Acceptance command:** `./scripts/verify-clean-room-boundary.sh`
- **Cost/network effects:** local filesystem and Git reads only; no network or payment.
- **Secrets involved:** none.
- **Evidence produced:** command output plus this ticket and the build journal.
- **Parking lot:** runtime/database/queue selection; package/lockfile; formatting/lint/tests; secret scanner; CI; environment schema; staging and rollback.
- **Stop condition:** acceptance and failure tests pass, handoff names N0.2, commit N0.1, then stop.

- **Deployment checked:** not applicable; N0.1 authorizes no deployment.
