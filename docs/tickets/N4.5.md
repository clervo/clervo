# N4.5 — Build deterministic query planning and parallel two-path retrieval federation

## Ticket

- **Stage:** 4 — Search vertical slice.
- **One question:** Can one identity-bound query execute against exactly two qualified independent paths in parallel with immutable provenance, one absolute deadline, linked cancellation, and explicit partial-failure accounting without beginning synthesis?
- **Inputs allowed:** controlling plan; repository-local N4.1–N4.4 contracts and fixtures. No live provider, credential, billable call, archive object read, browser, model, cloud/IAM mutation, legacy runtime, or payment.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Create a deterministic query plan from a currently valid two-path qualification snapshot, bind it by canonical SHA-256, and execute exactly one primary and one fallback adapter concurrently under one absolute deadline. Revalidate qualification identity/hash at execution, isolate path failures, propagate caller cancellation through per-path abort signals, reject malformed adapter metadata, preserve raw-response hashes and source ordinals, and derive complete/partial/failed/cancelled outcomes from exactly two immutable attempts using fixed safe failure codes.

## Build output

- Query-plan, adapter, candidate-observation, attempt, and federation-report TypeScript contracts and implementation.
- Qualification reconstruction/hash matching, strict plan validation, parallel execution, absolute deadlines, cancellation, late-settlement isolation, provenance hashing, bounded candidate validation, and deep immutability.
- One strict Draft 2020-12 federation-report schema, positive fixture, and false-success negative fixture.
- Eleven focused tests covering normalized planning, closed/stale gates, unsafe deadlines, actual parallel start, deterministic ordering, partial failure, safe error codes, malformed metadata, provenance hashes, deadline expiry, pre/in-flight cancellation, late settlement, forged plan/qualification rejection, elapsed deadlines, and immutability.
- Deterministic generated OpenAPI/schema artifacts plus decision, ticket, journal, README, and controlling-plan handoff.

## Validation contract

- **Focused tests:** `npm run contracts` and `npm run test:n4.5`.
- **Failure test:** closed/stale/substituted qualification, forged plan metadata, duplicate failure domains, unsafe deadlines, missing/rejecting/hanging adapters, malformed candidates, raw-response hashing failure, caller cancellation, and late settlement fail closed without losing the peer path's accounting.
- **Acceptance command:** `npm test`, `npm run generate:discovery`, source/generated schema semantic parity, `npm run staging:smoke`, and `git diff --check`.
- **Cost/network effects:** repository-local validation only; no provider, crawler, archive, browser, model, cloud/IAM/deployment mutation, wallet/payment, external traffic, or USDC spend.
- **Parking lot:** provider-specific Brave/Common Crawl adapters and live qualification; query expansion; fetch/extract/dedup/rank/citation assembly; synthesis; benchmarks; HTTP/mock-paid integration; durable orchestration.
