# N4.12 — Implement and test bounded query rewriting

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can retrieval gain a deterministic second query form without model inference, token expansion, provider coupling, or weakening operation and qualification bindings?
- **Inputs allowed:** the normalized user query, operation identity, timestamp, existing N4.2 qualification snapshot, and N4.5 federation boundary. No network, provider/model/browser calls, secrets, deployment mutation, payment, or USDC spend.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Create exactly two token-preserving variants: the normalized identity query and an escaped exact-phrase query. Cap input at 2,000 characters and 64 whitespace-delimited tokens. Bind the immutable rewrite artifact by SHA-256 into the federation plan, route identity to primary and exact phrase to fallback, and retain the normalized original as the response query.

## Validation contract

- **Focused test:** `npm run test:n4.12`.
- **Failure test:** control text, excess tokens/characters, artifact substitution, and execution-query substitution fail closed.
- **Acceptance:** canonical repository acceptance, staging loopback smoke, boundary verification, secret scan, and diff checks.
- **Cost/network effects:** no external traffic and 0 USDC spent.
