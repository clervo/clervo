# N4.21 — Isolated SearXNG loopback and direct Common Crawl WARC proof

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can one repository-controlled loopback SearXNG development composition and one independent direct Common Crawl index-to-WARC range path execute within strict identity, byte, freshness, safety, truthfulness, and zero-USDC bounds?
- **Freshness date:** 2026-07-31.
- **Secrets involved:** none. The checked-in SearXNG key is explicitly non-confidential, development-only loopback configuration material.

## Current-state preflight and decision

Primary evidence was limited to the current official SearXNG repository at commit `057a77168d3175ce2e42e5b10f46a8df073886d5`, its engine settings/source, and the current Common Crawl `CC-MAIN-2026-30` index and archive services. The selected composition keeps exactly two SearXNG engines: Wikipedia and OpenStreetMap. The OpenStreetMap engine is constrained to one public Nominatim result with extra tags disabled so it cannot add Wikidata as a third upstream.

A Docker engine and Compose were installed first. A privileged daemon started, but image-layer registration failed because the outer container denied mount-namespace creation. A rootless repair using user namespaces, RootlessKit, slirp4netns, and fuse-overlayfs also failed because the outer host denied subordinate UID/GID mapping. Rather than claim container isolation, the proof used the official commit in a dedicated Python virtual environment and a dedicated Granian process bound only to `127.0.0.1:18888`. Public/shared SearXNG, a remote bind, additional engines, and changes to the N4.18 service were rejected.

## Live result and limits

- The loopback broker returned HTTP 200 and one result for each configured engine with no unresponsive engine. It was stopped after the bounded proof.
- The first Common Crawl index attempt returned HTTP 502 and failed closed: no range request was derived. The single repair returned one exact 467-byte index record.
- That record authorized exactly `bytes=215767931-215768884`, a 954-byte range. `data.commoncrawl.org` returned HTTP 206, the exact `Content-Range`, and a gzip member whose compressed and decoded hashes matched the recorded evidence.
- This proves a development composition and direct archive mechanics only. Wikipedia and public Nominatim do not establish general-Web quality. Public Nominatim resale remains prohibited. Common Crawl content use remains subject to origin-rights/legal review. No provider is connected to a Clervo product or staging route.
