# N4.16 — Publish separate raw retrieval and synthesis prices

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can raw retrieval and synthesized answers be represented as separately priced products whose catalog, request, quote, payment, execution, receipt, and idempotency identities cannot be confused?
- **Inputs allowed:** existing search request modes, deterministic contract/hash functions, mock commerce, generated discovery, repository-local HTTP tests, and recorded search execution. No external provider, cloud/IAM mutation, real payment, or USDC spend.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Keep `search.query` as the stable HTTP operation. Select `search.web` exactly when `synthesize=false` and `search.answer` exactly when `synthesize=true`, including the existing default. Publish fixed mock-USDC catalog prices of 1000 atomic units for raw retrieval and 2500 atomic units for synthesis, each with a distinct price version. Bind the selected product into canonical request identity, execution input and output, quote, challenge, receipt, and discovery.

## Validation contract

- **Focused test:** `npm run test:n4.16`.
- **Failure test:** cross-product quote/payment reuse, cross-product idempotency replay, product-mode drift, and missing synthesis output fail closed before unauthorized execution or receipt construction.
- **Acceptance:** canonical repository acceptance, schema/discovery generation, Stage 4 recomputation, staging loopback smoke, boundary verification, secret scan, and diff checks.
- **Cost/network effects:** no external traffic and 0 USDC spent.

## Completion

- **Result:** separate raw retrieval and synthesis prices are repository-verified and bound through the mock commerce path; public payment and staging behavior remain unverified.
- **Stage effect:** `separate_raw_and_synthesis_prices` advances from `missing` to `repository_verified`, but remains `stagingVerified=false`; Stage 4 remains blocked.
