# N4.14 — Implement disclosed cache freshness

## Ticket

- **Stage:** 4 — Search vertical slice remediation.
- **One question:** Can every search response disclose whether it was an origin miss, a fresh cache hit, or a stale entry revalidated before reuse, with freshness claims bound to the exact request and returned representation?
- **Inputs allowed:** normalized query, requested result bound, completed search response material, timestamps, and explicit cache evidence. No external network, durable cache deployment, cloud/IAM mutation, payment, or USDC spend.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Require a `search_cache_disclosure_v1` artifact on every `SearchResponse`. Bind it by canonical SHA-256 to the query/result bound and the exact response material. Recompute age, resident age, remaining freshness, and revalidation semantics. The current recorded pipeline truthfully emits `miss`; future callers may claim hits only by providing timelines that pass fail-closed validation.

## Validation contract

- **Focused test:** `npm run test:n4.14`.
- **Failure test:** expiration-boundary hits, future timestamps, non-stale revalidation claims, non-current revalidation, request/response substitution, result-bound drift, and derived-field/hash tampering fail closed.
- **Acceptance:** canonical repository acceptance, schema/discovery generation, Stage 4 recomputation, staging loopback smoke, boundary verification, secret scan, and diff checks.
- **Cost/network effects:** no external traffic and 0 USDC spent.

## Completion

- **Result:** disclosed cache freshness is repository-verified for `miss`, `fresh_hit`, and `stale_revalidated`; no durable cache or staging cache behavior is claimed.
- **Focused validation:** `npm run test:n4.14` passed 5/5.
- **Canonical validation:** acceptance passed 155/155 with 32 strict schemas and 60 fixtures under Node.js 24.18.1/npm 10.9.8. Loopback staging smoke, clean-room boundary, working-tree/full-history secret scan, discovery generation, Stage 4 recomputation, and diff checks passed.
- **Deployment checked:** checked-in staging state and loopback HTTP only. No live cache, provider/model/browser, cloud/IAM mutation, public deployment, payment, or external network was exercised.
- **Stage effect:** `disclosed_cache_freshness` advances from `missing` to `repository_verified`, but remains `stagingVerified=false`; Stage 4 remains blocked.
