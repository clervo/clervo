# N1.1 — Define envelopes, errors, operation states, and idempotency

## Ticket

- **Stage:** 1 — Contracts and lifecycle
- **One question:** Can every future Clervo operation share a strict, versioned, replay-safe lifecycle contract that prevents duplicate work and fails closed on unknown outcomes?
- **Why it blocks the stage:** Catalog, adapters, OpenAPI, quotes, x402, ledger, and reconciliation cannot safely converge without common request/result/error shapes and state semantics.
- **Inputs allowed:** controlling plan; Stage 0 decisions; official JSON Schema, RFC 9457, RFC 8785, and IETF idempotency draft evidence; maintained schema-validation packages. No legacy implementation or state.
- **Preflight scope:** standards, validators, canonicalization, lifecycle safety, replay semantics, licenses, and local tooling.
- **Research limit:** bounded to the current session.
- **Freshness date:** 2026-07-29.
- **Secrets involved:** none.

## Decision

Adopt versioned Draft 2020-12 JSON Schemas, RFC 9457 problem details, an explicit 17-state operation lifecycle with fail-closed unknown states, and a Clervo-owned idempotency contract using restricted caller keys plus SHA-256 of RFC 8785/JCS canonical request material.

## Build output

- TypeScript contract package for envelopes, problem types, canonical request hashes, idempotency decisions, and state transitions.
- Four strict wire/durable schemas and valid/invalid fixtures.
- Ajv 2020-12 validation, TypeScript compilation, repository lint, and adversarial contract tests.
- ADR-0004, ticket evidence, journal/README updates, and next-ticket handoff.

## Validation contract

- **Focused tests:** strict typecheck/build; all schemas compile; fixtures match expected validity; canonical fingerprints are stable across member order; state gates and replay decisions behave exactly as declared.
- **Failure test:** altered request under an existing key must conflict; unknown execution/settlement cannot retry directly; undeclared response/problem fields must fail schema validation.
- **Acceptance command:** `npm test` under Node.js 24.
- **Cost/network effects:** read-only standards/web and npm metadata requests plus dependency install; no provider/cloud/deployment/payment mutations; 0 USDC.
- **Evidence produced:** source, schemas, fixtures, validators, tests, ADR, ticket, journal, README, and handoff.
- **Parking lot:** database tables/transactions; HTTP handlers and status mapping; per-operation input/output schemas; catalog/adapter/receipt/audit contracts; OpenAPI; binary/stream fingerprints; distributed concurrency tests.
- **Stop condition:** acceptance and explicit failure tests pass, evidence is committed, handoff names N1.2, then stop.
