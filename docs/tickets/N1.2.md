# N1.2 — Define catalog, adapter, receipt, and audit contracts

## Ticket

- **Stage:** 1 — Contracts, catalog, and operations
- **One question:** Can Clervo describe purchasable products and replaceable suppliers, prove qualification and delivery, and record useful evidence without provider coupling, silent substitution, secret leakage, or premature payment implementation?
- **Why it blocks the stage:** OpenAPI/discovery, routing, adapters, commerce, observability, and mock vertical slices cannot converge without canonical catalog, qualification, receipt, and audit shapes.
- **Inputs allowed:** controlling plan; completed N1.1 contracts; official JSON Schema/RFC 3339/W3C trace/SPDX evidence; current repository conventions. No legacy runtime implementation or state.
- **Preflight scope:** product activation invariants, provider replaceability, qualification evidence, immutable hash material, redaction-by-construction, trace identifiers, terms metadata, licenses, and local tooling.
- **Research limit:** bounded to the current session.
- **Freshness date:** 2026-07-29.
- **Secrets involved:** names only in adapter manifests; no values.

## Decision

Adopt strict Draft 2020-12 catalog/adapter/qualification/receipt/audit schemas plus TypeScript source contracts. Active catalog entries fail closed without lawful qualified supply and charge ceilings; exact identities cannot substitute; adapter methods remain provider neutral; receipts and audit events are canonical SHA-256 hash-bound and exclude payload/credential/payment proof material.

## Build output

- TypeScript catalog activation, adapter interface, qualification gate, deterministic receipt, and allowlisted audit contracts.
- Five new strict schemas and nine new positive/negative fixtures, bringing the package total to nine schemas and fifteen fixtures.
- Seven focused adversarial tests for activation, identity substitution, qualification, receipt determinism/tampering, and audit redaction/tampering.
- ADR-0005, ticket evidence, journal/README updates, and next-ticket handoff.
