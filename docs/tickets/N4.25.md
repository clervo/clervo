## Current-state preflight and decision

N4.23A already reviewed the current Crawl4AI `0.9.2` and Playwright `1.61.0` primary sources and exact artifacts. N4.25 reused that bounded evidence rather than making new network calls. The container preflight found no Docker, Podman, Crawl4AI, Playwright, or authenticated staging identity. Therefore a raw Crawl4AI HTTP service, direct worker Internet egress, an unpinned image, and any `ready` claim were rejected.

The selected architecture is a two-plane internal worker. Crawl4AI/Chromium has no Service or ingress and can reach only a separate retrieval-authorization gateway. The gateway—not page content or the browser—authorizes every document and asset URL, DNS result, connected address, and redirect. The worker has no service-account token, host namespace/mount/socket, metadata/control-plane/database/commerce-secret access, persistent state, downloads, login/cookies, caller JavaScript/hooks, LLM integration, CAPTCHA solving, proxy rotation, stealth, or access-control bypass. Exact runtime attestation is mandatory before lifecycle `ready`; absent or invalid proof is `unavailable`.

Durable retrieval cache keys bind the normalized current URL, exact focused/live route identity, and exact request-policy hash. Records are environment namespaced, content-addressed, checksummed, atomically replaced, and safety-declared; cross-route substitution or corruption evicts to a miss. PostgreSQL 18 is the production durability boundary already selected by ADR-0002; a filesystem adapter provides deterministic local durability evidence. Redis/new cache infrastructure was rejected as unnecessary scope. Stale data is reusable only while upstream is degraded and only with visible stale disclosure.
