# N4.8 — Benchmark recorded search quality against a BlockRun-compatible baseline

## Ticket

- **Stage:** 4 — Search vertical slice.
- **One question:** Can repository-local recorded search/synthesis observations be evaluated by an independent, deterministic, fail-closed harness across relevance, freshness, citation validity, duplicate suppression, adversarial injection, provider failure, latency, cost, and improvement over a named BlockRun-compatible baseline?
- **Inputs allowed:** controlling plan; repository-local N4.1–N4.7 contracts; synthetic/recorded observations containing no credentials or live-provider claims. No provider call, model call, external fetch, cloud/IAM mutation, deployment, wallet, payment, or USDC spend.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Add a pure evaluator over immutable recorded observations. Ground truth, expected failure behavior, prohibited answer text, category membership, thresholds, and corpus identity are inputs; recall, freshness, citation validity, duplicate rate, p95 latency, average recorded cost, injection behavior, provider-failure behavior, aggregate quality, baseline improvement, and pass/fail codes are recomputed rather than accepted from a candidate report.

## Build output

- Versioned benchmark input/report contracts, six required categories, fixed failure codes, canonical corpus hashing, category-aware aggregation, and immutable results.
- Independent exact-citation verification against recorded search evidence and fail-closed zero-citation handling when synthesis was expected.
- Strict Draft 2020-12 report schema, valid fixture, false-pass invalid fixture, and six adversarial tests.
- Canonical test wiring and generated discovery/schema artifacts.

## Validation contract

- **Focused tests:** `npm run contracts` and `npm run test:n4.8`.
- **Failure test:** missing categories, duplicate case IDs, unbound observations, invalid citations, excessive latency/cost, prohibited injected answer text, incorrect provider-failure outcome, and insufficient baseline improvement fail closed.
- **Acceptance command:** `npm test`, `npm run generate:discovery`, source/generated schema semantic parity, `npm run staging:smoke`, and `git diff --check`.
- **Cost/network effects:** repository-local validation only; no provider, crawler, archive, external fetch, browser, model, cloud/IAM/deployment mutation, wallet/payment, external traffic, or USDC spend.
- **Parking lot:** calibrated large/live corpus; human relevance judgments; live Brave/Common Crawl quality, cost, quota, and latency; production SLOs; free-sample and paid HTTP routes; durable benchmark history.

## Completion

- **Result:** repository-local recorded benchmark mechanics implemented. The six-case acceptance corpus reports candidate quality `10000` basis points, baseline quality `1600`, and improvement `8400`; these values describe only the synthetic recorded corpus and are not live-quality claims.
- **Focused tests:** `npm run test:n4.8` passed 6/6; contract validation counts are recorded in the build journal after canonical acceptance.
- **Repository-wide tests:** canonical `npm test` passed with exit code 0 while executing the exact pinned Node.js `24.18.1` runtime and npm `10.9.8`: lint/typecheck, clean-room boundary, stack/environment checks, working-tree plus full-history secret scan, N0.3 injected-secret rejection/cleanup, 27 schemas/51 fixtures, deterministic discovery, and N1.1 through N4.8 at 126/126 TAP tests.
- **Exact next ticket:** define and implement the bounded free-sample HTTP route over the completed search pipeline without payment exposure; keep mock-paid routing separate.
