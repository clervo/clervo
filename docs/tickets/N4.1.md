# N4.1 — Build deterministic search result integrity

## Ticket

- **Stage:** 4 — Search vertical slice
- **One question:** Can normalized search evidence be deduplicated, ranked, and cited deterministically without accepting unsupported citations or overstating result quality?
- **Inputs allowed:** controlling plan; repository-local contracts and validation conventions. No legacy runtime, live provider, crawler, browser, model, or external search traffic.
- **Freshness date:** 2026-07-30.
- **Secrets involved:** none.

## Decision

Define the stable search evidence/result/citation/response boundary; implement conservative HTTP(S) URL canonicalization, exact canonical-URL deduplication, transparent integer scoring, stable ranking, and exact evidence-offset citation verification.

## Build output

- Search TypeScript contracts and deterministic canonicalization, ranking, deduplication, response, and citation-verification functions.
- One strict Draft 2020-12 search-response schema with positive and adversarial fixtures.
- Nine focused tests covering URL normalization, unsafe URL rejection, deterministic duplicate selection, stable ranking, freshness/diversity components, malformed evidence, exact citations, citation failures, immutability, and honest deduplication counts.
- Decision record, ticket evidence, journal/README updates, generated public schema refresh, and next-ticket handoff.

- **Focused tests:** `npm run contracts` and `npm run test:n4.1`.
- **Failure test:** malformed/non-HTTP URLs, embedded credentials, future evidence, invalid scores, duplicate IDs, missing results, mismatched citation URLs/text, and invalid offsets must fail closed.
- **Acceptance command:** `npm test` plus `npm run staging:smoke`.
- **Cost/network effects:** repository-local tests only; no provider, crawler, browser, model, wallet, cloud, IAM, deployment, payment, or external traffic; 0 USDC.
- **Parking lot:** retrieval/extraction tool selection, two independent lawful paths, semantic near-duplicate detection, query rewriting, SSRF/browser isolation, prompt-injection boundaries, synthesis, benchmarks, and free/mock-paid HTTP paths.
- **Stop condition:** focused and repository-wide acceptance pass, evidence is recorded, and the controlling-plan handoff names N4.2.
